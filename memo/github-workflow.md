# GitHub Issue と連携した作業手順

Issue 番号は memo の項目番号と一致しない（項目 1〜12 → #2〜#13、項目 13〜20 → #15〜#22）。作業前に必ず対応を確認する。

1. **Issue の確認**
   - `gh issue view <番号> -R ngkazu/aedt-launcher` で本文を確認する。
2. **作業ブランチの作成**
   - `main` を最新にしてから `fix/<番号>-<内容>` のブランチを切る（例: `fix/20-app-manifest-assemblyinfo`）。
3. **変更内容の提案と承認**
   - 変更前に方針を提示し、承認を得る。
   - 著作権年など意図の確認が必要な点は、必ず質問する。
4. **実装と検証**
   - 承認後に変更する。
   - Debug と Release の両方をビルドし、警告が増えていないことを確認する。
   - exe を起動し、ファイルのドロップと Launch が従来どおり動くことを確認する。
5. **コミット**
   - コミットメッセージは英語で、末尾に Co-authored-by トレーラーを付ける。
   - 本文に `Refs #<番号>` を書く。PR で閉じる場合は `Fixes #<番号>` を使う。
   - コミットは依頼があったときだけ行う。
6. **push と PR 作成**
   - `git push -u origin <ブランチ名>` でブランチを push する。
   - `gh pr create -R ngkazu/aedt-launcher --base main --title "..." --body "Fixes #<番号>"` で PR を作成する。
7. **マージとクローズ**
   - PR を `main` にマージすると、`Fixes #<番号>` により Issue が自動でクローズされる。
   - マージ後は `main` を pull し、作業ブランチを削除する。
8. **メモの更新**
   - 完了した項目の `終了フラグ` を `[x]` に更新するかは、都度確認する。
